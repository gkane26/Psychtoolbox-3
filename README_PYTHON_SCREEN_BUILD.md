## Build Process

### 1. Initial Compilation Issue

The first attempt to build the Screen module failed with an undefined symbol error:

```
ImportError: undefined symbol: LoadEXR
```

**Root Cause**: The `LoadEXR` function is implemented in `tinyexr.cc`, a C++ file that provides HDR/EXR image loading support. The build system was only compiling C files, leaving the C++ functionality unlinked.

### 2. Solution: Mixed C/C++ Compilation

**Step 1: Manually compile the C++ component**

```bash
cd PsychSourceGL/Source/Common/Screen/
g++ -c -fPIC -O2 tinyexr.cc -o tinyexr.o
```

**Step 2: Modify setup.py to link the object file**

Added the following lines to `setup.py` in the Linux Screen module section:

```python
# Screen module: Graphics, multimedia, windows. This is the core module of PTB
if platform.system() == 'Linux':
    screen_libs = base_libs + ['GL', 'GLU', 'X11', 'Xext', 'X11-xcb', 'xcb', 
                              'xcb-dri3', 'xcb-present', 'xcb-sync', 'Xcomposite', 
                              'Xfixes', 'Xrandr', 'Xxf86vm', 'pciaccess', 'Xi']
    screen_compile_args = base_compile_args + ['-DPTBMODULE_Screen', '-DGLEW_STATIC']
    screen_includes = ['/usr/X11R6/include']
    
    # Add compiled C++ object for HDR support
    screen_objects = ['PsychSourceGL/Source/Common/Screen/tinyexr.o']
    
    name = 'Screen'
    Screen = Extension(name,
                      extra_compile_args = screen_compile_args,
                      define_macros = get_basemacros(name, osname),
                      include_dirs = get_baseincludedirs(name, osname) + screen_includes,
                      sources = get_basesources(name, osname),
                      libraries = screen_libs,
                      extra_objects = screen_objects,  # Link the C++ object
                      py_limited_api = py_limited_api,
                     )
    ext_modules.append(Screen)
```

## Pythonic Screen API

### Overview

We created a Pythonic wrapper (`psychtoolbox.screen.PTBScreen`) that maintains the MATLAB-style workflow while providing cleaner Python syntax. The API preserves the original design where windows are just reference handles, not objects with methods.

### Key Features

- **MATLAB-compatible syntax**: Functions take window pointers as arguments
- **Proper argument handling**: Uses default values (empty lists `[]`) for optional parameters
- **Positional argument preservation**: Arguments are passed in the correct order to underlying Screen functions
- **Comprehensive coverage**: Includes all major Screen functions

### Example Usage

```python
from psychtoolbox.screen import PTBScreen
import numpy as np

# Create screen interface
screen = PTBScreen()

# Get available screens
screens = screen.screens()
print(f"Available screens: {screens}")

# Open a window (returns window pointer like MATLAB)
window_ptr, rect = screen.open_window(
    screen_number=0, 
    color=[128, 128, 128],  # Gray background
    rect=[0, 0, 800, 600]   # Window size
)

# Create a texture from image data
image_data = np.random.rand(100, 100, 3) * 255
image_data = image_data.astype(np.uint8)
texture = screen.make_texture(window_ptr, image_data)

# Draw the texture
screen.draw_texture(
    window_ptr, 
    texture,
    dest_rect=[100, 100, 200, 200]  # Position and size
)

# Draw some shapes
screen.fill_rect(window_ptr, color=[255, 0, 0], rect=[300, 300, 400, 400])
screen.fill_oval(window_ptr, color=[0, 255, 0], rect=[500, 300, 600, 400])

# Draw text
screen.text_size(window_ptr, 24)
screen.draw_text(window_ptr, "Hello Psychtoolbox!", x=50, y=50)

# Present the stimulus
vbl_timestamp, onset_time, flip_timestamp, missed, beampos = screen.flip(window_ptr)

# Wait and clean up
import time
time.sleep(2.0)
screen.close(window_ptr)
# or close all windows: screen.close_all()
```

## Technical Details

### Mixed C/C++ Compilation Strategy

The solution uses a two-stage compilation approach:

1. **Stage 1**: Manually compile C++ components using `g++` with appropriate flags
2. **Stage 2**: Link the resulting object files during Python extension compilation using `extra_objects`

This approach is necessary because:
- Python's distutils/setuptools doesn't handle mixed C/C++ compilation well
- The tinyexr library requires C++ features not available in C
- The main Screen module is written in C but needs C++ functionality

### Argument Handling in Pythonic API

The wrapper uses Python default arguments to maintain MATLAB-style positional parameter behavior:

```python
def open_window(self, screen_number, color=[], rect=[], pixel_size=[], ...):
    return Screen('OpenWindow', screen_number, color, rect, pixel_size, ...)
```

This ensures that:
- All arguments are passed in the correct positional order
- Empty lists `[]` are used as defaults (Psychtoolbox convention)
- Users can skip intermediate arguments like in MATLAB

## Troubleshooting

### Common Issues

**1. ImportError: undefined symbol**
- Ensure all required system libraries are installed
- Check that tinyexr.o was compiled successfully
- Verify setup.py includes the extra_objects parameter

**2. X11 connection issues**
- Set `DISPLAY=:0` environment variable for SSH connections
- Ensure X11 forwarding is enabled if using remote connections
- Install required X11 development libraries

**3. Audio device errors**
- Install PortAudio development libraries
- Check ALSA configuration
- Verify audio device permissions

**4. Data type errors (colors/rectangles)**
- Colors should be passed as lists: `[255, 0, 0]` not numpy arrays
- Rectangles should be passed as lists: `[0, 0, 800, 600]` not numpy arrays
- The Pythonic wrapper automatically converts these to the correct format
- For sync issues, use: `Screen('Preference', 'SkipSyncTests', 1)` for development
